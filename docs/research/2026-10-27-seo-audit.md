# Weekly SEO audit: apps/marketing, 2026-10-27

Scope: all 32 URLs in `sitemap.xml` on https://www.homeownerledger.online, plus the code in `apps/marketing`. Method: `curl`/Node fetch of every page (title, description, canonical, Open Graph, H1 count, heading order, `<img>` alt, JSON-LD parsed and checked for required fields, internal link graph), then `pnpm --filter marketing build` for first-load JS. Fixes are in this branch; the live site shows the "before" state until it deploys.

Checks that were already clean: all 32 URLs return 200; every canonical equals its own `https://www.homeownerledger.online/...` URL; every page has exactly one H1; titles and descriptions are unique; all JSON-LD parses and carries its required fields (Organization, Article, FAQPage, BreadcrumbList, HowTo, WebPage, ItemList); no internal link returns a non-200; there are no `<img>` tags, so no missing alt text; `robots.txt` allows all, lists the host and the sitemap; `sitemap.xml` has 32 `<loc>` and 32 `<lastmod>`, and it matches the pages the code renders (already enforced by `marketing-truth.test.ts`).

## Performance (first-load JS per route)

Shared by all routes: 170 kB (React and Next runtime, 54 + 112 kB). Most routes sit at 190-194 kB.

Cause of the 229-233 kB routes: five client components used the full `motion` element from framer-motion (it bundles animation, gesture and layout code synchronously). Fix: `MotionProvider` now uses `LazyMotion` with the `domMax` feature set loaded on demand (`components/site/motion-features.ts`), and all components use the slim `m` element. This removed about 28 kB per affected route.

| Route | Before | After |
|---|---|---|
| /hoa | 233 kB | 205 kB |
| /security | 229 kB | 202 kB |
| /roadmap | 229 kB | 201 kB |
| /honesty-bars | 229 kB | 201 kB |

Still 1-5 kB over 200. I also tried `next/dynamic` on the heavy client components (bar explorer, roadmap table, audit log, violation drafter); it did not lower first-load JS because server-rendered dynamic chunks are preloaded, so it was reverted. Getting under 200 needs `ssr: false` behind a client wrapper (which would drop that content from the HTML) or trimming `AnimatePresence`/`domMax` usage. Next step: replace `domMax` with `domAnimation` and drop `layout` animation on the three components that use it, which should recover the last few kB.
