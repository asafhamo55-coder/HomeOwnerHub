# HeyGen resident welcome video

A presenter-led version of the welcome video. Same script and six steps as `apps/hoa/src/app/welcome/transcript.ts`, spoken by a HeyGen avatar over branded screen backgrounds (blue and green brand, sample data only).

Nothing here replaces the live video. The current files in `apps/hoa/public/welcome` stay as the fallback until the owner approves the result.

## Files

- `scenes.json`: 9 scenes (line, target seconds, background, caption), about 2 minutes in total, speech speed 0.9.
- `render-backgrounds.mjs`: draws the stills into `backgrounds/` from the screen markup in `tools/welcome-video`. Portrait 1080x1920 (phone on top, lower third left clear for the presenter), landscape 1920x1080 (phone on the left, right side clear).
- `generate.mjs`: talks to HeyGen. No dependencies, Node 20 or newer, plus `ffmpeg` to join the scenes.
- `generate.test.ts`: unit tests with a mocked fetch (run by `pnpm test:unit`).

## One-time setup

Create `~/.config/homeownerhub/heygen.env` with one line:

```
HEYGEN_API_KEY=your-key-here
```

The key is only sent in the `x-api-key` header. It is never printed, logged or written anywhere else.

## Commands

```bash
# 1. (optional) redraw the backgrounds
node tools/welcome-video-heygen/render-backgrounds.mjs

# 2. choose an avatar and a voice
node tools/welcome-video-heygen/generate.mjs --list

# 3. preview the requests, calls nothing, key redacted
node tools/welcome-video-heygen/generate.mjs --avatar <id> --voice <id> --orientation portrait --dry-run

# 4. make the videos
node tools/welcome-video-heygen/generate.mjs --avatar <id> --voice <id> --orientation portrait
node tools/welcome-video-heygen/generate.mjs --avatar <id> --voice <id> --orientation landscape
```

Output: `tools/welcome-video-heygen/out/welcome-heygen-portrait.mp4` and `welcome-heygen-landscape.mp4` (git-ignored; the per-scene files are in `out/parts-<orientation>/`).

`--list` prints public avatars (id, name, gender, type, orientation) and English voices (id, name, language, preview link). HeyGen's voice list has no gender field, so use the preview links. For an older audience pick a calm, warm voice. An avatar's own default voice is often a good match.

## API notes

HeyGen retired v1 and v2, so this uses the v3 API (`developers.heygen.com`):

- `POST /v3/assets` uploads each background (multipart) and returns an `asset_id`.
- `POST /v3/videos` with `type: "avatar"` renders ONE scene. So each scene in `scenes.json` becomes its own video, and `generate.mjs` joins them with ffmpeg. Each request carries the avatar, voice, line, `voice_settings.speed` 0.9, the background `asset_id`, `aspect_ratio` (9:16 or 16:9), 1080p and `caption.style: "default"` (burned-in captions).
- `GET /v3/videos/{id}` is polled every 10 seconds until `completed`, then `video_url` is downloaded.

Unknown until the first real run: HeyGen's docs give no scale or offset control for the avatar, so where the presenter sits in the frame is chosen by HeyGen. The backgrounds leave the lower third (portrait) and the right side (landscape) clear, but check the first result. If the presenter covers the phone, tell the team and we will adjust the layouts or use a different avatar framing.

## Cost estimate

HeyGen does not publish per-minute API prices in its developer docs (they are behind the sign-in at platform.heygen.com/pricing), and the API balance is separate from web plan credits. Third-party summaries of HeyGen's pay-as-you-go list, not verified:

| Avatar type | Approx. price per finished minute |
|---|---|
| Avatar III digital twin | $0.60 |
| Avatar III studio or photo avatar | $0.99 |
| Avatar IV photo avatar | $2.31 |
| Avatar IV digital twin or studio avatar | $4.83 |

The video is about 2 minutes, so roughly **$1.20 to $10 per orientation**, or $2.40 to $20 for both. Check the price and your balance on the HeyGen pricing page before the first run. Billing is by seconds generated, so a re-run costs the same again.

## Swapping the result in (after the owner approves)

The app plays `apps/hoa/public/welcome/welcome.mp4` (portrait) and `welcome-landscape.mp4`, with posters `poster.jpg` and `poster-land.jpg`.

```bash
cd apps/hoa/public/welcome
mkdir -p previous && cp welcome.mp4 welcome-landscape.mp4 poster.jpg poster-land.jpg previous/   # keep the fallback
cp ../../../../tools/welcome-video-heygen/out/welcome-heygen-portrait.mp4  welcome.mp4
cp ../../../../tools/welcome-video-heygen/out/welcome-heygen-landscape.mp4 welcome-landscape.mp4
ffmpeg -y -ss 3 -i welcome.mp4           -frames:v 1 -q:v 3 poster.jpg
ffmpeg -y -ss 3 -i welcome-landscape.mp4 -frames:v 1 -q:v 3 poster-land.jpg
```

Then:

1. Update `apps/hoa/src/app/welcome/transcript.ts` only if the spoken words changed (it is generated by `tools/welcome-video/render.mjs`; the HeyGen lines in `scenes.json` use the same words).
2. Check the file sizes (the current videos are about 10 MB each; every committed re-render stays in git history forever) and run the app build.
3. Delete `previous/` once the new video has been live without complaints.
